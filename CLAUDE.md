# Threads-автопостер: инструкция для Claude Code

Ты разворачиваешь и сопровождаешь бота, который сам пишет и публикует пост в Threads: «Бюро Этожеты!» — 3 раза в сутки (11:00, 16:00 и 21:00 МСК, аккаунт @pomazkof), «Олоид» — 3 раза в сутки (10:00, 15:00 и 20:00 МСК, аккаунт @oloid.vn).
Он продвигает два проекта владельца (Илья): сервис детективных вечеров «Бюро Этожеты!» (etozhety.ru) и визуальную новеллу «Олоид» (лендинг oloid-game.ru; страница Steam пока не публичная).
Режим полностью автоматический: перед публикацией посты никто не смотрит. Поэтому проверки в коде и правила ниже — единственная защита. Не ослабляй их.

## Как устроен проект

```
api/cron.ts      — ПУБЛИКУЮЩИЙ эндпоинт. Его вызывает Vercel Cron с заголовком Authorization: Bearer $CRON_SECRET
api/preview.ts   — холостой прогон: генерирует пост и возвращает текст. Модуль публикации не подключает
lib/run.ts       — выбор проекта/рубрики + генерация с проверками (общий для cron и preview)
lib/generate.ts  — промпты к Claude API, механические правила, антиповтор, фактчек вторым проходом
lib/projects.ts  — «паспорта» проектов: голос, ФАКТЫ, запреты, рубрики. Единственный источник фактов
lib/threads.ts   — Threads API: создание контейнера → публикация, автопродление токена
lib/store.ts     — Redis (по REDIS_URL, клиент `redis`): история постов, токен Threads, последний проект
lib/channels.ts  — аккаунты Threads: токен (переменная окружения), проекты, поправка голоса. Крон вызывает /api/cron?channel=<id>
vercel.json      — расписание кронов (отдельный крон на слот, каждый раз в сутки: Бюро 11:00/16:00/21:00 МСК, Олоид 10:00/15:00/20:00 МСК; МСК = UTC+3) и таймауты функций
public/media/    — видео для постов (Meta скачивает их по ссылке с домена бота). Кроме public/ наружу ничего не раздаётся
```

Один запуск крона:
1. У аккаунта один проект — постится он (@pomazkof — только Бюро, @oloid.vn — только Олоид). Если проектов несколько, они идут по очереди.
2. Рубрика выбирается по весам и не повторяет предыдущую рубрику этого проекта.
3. Пост генерируется и проходит три фильтра: правила → антиповтор → фактчек. У «Бюро» в каждом посте одна мемная отсылка к детективу, и она не повторяет недавние.
4. Если вариант не прошёл, генерация повторяется до 3 раз. Если не прошли все попытки, этот слот пропускается.
5. Пост публикуется, запись уходит в историю, отчёт — в Telegram (если он настроен).

## Жёсткие правила для тебя

1. **Не снимай паузу без явного согласия Ильи в этой сессии.** Это касается `PAUSED=0`, удаления `PAUSED` и удаления `DRY_RUN`. Перед этим покажи ему 3–5 свежих превью по каждому проекту и дождись прямого «да, запускай».
2. **Не публикуй в Threads вручную.** Не вызывай `/api/cron` без `dry=1`. Публикует только крон.
3. **Не выдумывай факты.** В `facts` в `lib/projects.ts` добавляй только то, что Илья сказал сам: цены, даты, ссылки, акции. Если чего-то не хватает, спроси.
4. **Не ослабляй проверки ради прохождения поста.** Сюда относятся `ruleCheck`, `tooSimilar`, `factCheck`, список `forbidden` и порог длины. Если посты регулярно отклоняются, покажи Илье причины из `rejected` и предложи правку голоса или фактов.
5. **Секреты не выводи в чат и не коммить.** Ключ Anthropic, токен Threads и токены Telegram Илья вводит сам: через `vercel env add` в своём терминале или в панели Vercel. `CRON_SECRET` и `PREVIEW_KEY` генерируй сам (`openssl rand -hex 24`) и сразу клади в Vercel.
6. **Спойлеры «Олоида» запрещены.** Нельзя писать о природе артефакта, путешествиях во времени, ритуале и разгадках убийств. Этот запрет стоит в `forbidden` — не убирай его.
7. **Сообщай, если что-то не проверено.** Код типизирован и правила протестированы локально. С живыми Threads API и Anthropic API бот ещё не запускался, поэтому первые реальные вызовы проверяй по логам.

## Первичная настройка

### Что делает Илья (тебе недоступно)
- [ ] **Приложение Meta.** developers.facebook.com/apps → Create App → без бизнес-портфолио → сценарий «Access the Threads API». Из РФ может понадобиться VPN.
- [ ] **Права.** Use cases → Customize: включить `threads_basic` и `threads_content_publish`.
- [ ] **Тестировщик.** Добавить свой аккаунт Threads в Threads Testers и принять приглашение на сайте Threads.
- [ ] **Токен.** Сгенерировать токен пользователя и обменять его на долгоживущий (~60 дней):
  `GET https://graph.threads.net/access_token?grant_type=th_exchange_token&client_secret=APP_SECRET&access_token=SHORT_TOKEN`
- [ ] **Redis.** Vercel → Storage → Marketplace → Redis, подключить к проекту. Пропишется `REDIS_URL`. Сделано: Redis от Redis Inc.
- [ ] **Telegram (по желанию).** Бот через @BotFather плюс свой chat id.

### Что делаешь ты
```bash
npm install
npx tsc --noEmit                       # типы должны сходиться
npx vercel login                       # если ещё не залогинен
npx vercel link                        # создать проект threads-autopost

# Предохранители — ДО первого деплоя
echo 1 | npx vercel env add PAUSED production
openssl rand -hex 24 | npx vercel env add CRON_SECRET production
openssl rand -hex 16 | npx vercel env add PREVIEW_KEY production
```
Затем попроси Илью ввести секреты в его терминале:
```bash
npx vercel env add ANTHROPIC_API_KEY production
npx vercel env add THREADS_ACCESS_TOKEN production
npx vercel env add TG_BOT_TOKEN production     # опционально
npx vercel env add TG_CHAT_ID production       # опционально
```
Деплой и проверка:
```bash
npx vercel deploy --prod
npx vercel env ls production   # убедиться, что PAUSED на месте
```

Модель по умолчанию — `claude-sonnet-5-5`, её можно переопределить через `ANTHROPIC_MODEL`.
Если API отвечает «model not found», сверь актуальный ID в документации Anthropic, не угадывай.

## Управление

Переменные окружения применяются только после передеплоя. После любого `env add/rm` запускай `npx vercel deploy --prod`.

| Задача | Как |
|---|---|
| Посмотреть превью поста | `curl "https://<домен>/api/preview?key=$PREVIEW_KEY&project=buro"` (или `oloid`), можно добавить `&rubric=<id>`, `&topic=<фрагмент темы>` и `&notify=1` (прислать превью в Telegram, в ответе поле `telegram`). `&whoami=1` — без генерации показывает, от имени какого аккаунта Threads будет постить бот (проверка токена). Поле `redis` в ответе показывает, видит ли бот базу. `PREVIEW_KEY` хранится как Sensitive и через `env pull` не достаётся: если локальной копии нет, перевыпусти его (`openssl rand -hex 16 | tr -d "\n" | npx vercel env add PREVIEW_KEY production --sensitive --force`) и задеплой |
| Остановить бота | `npx vercel env rm PAUSED production -y && echo 1 \| npx vercel env add PAUSED production` → деплой |
| Генерировать без публикации | `DRY_RUN=1` → деплой |
| Запустить (только с «да» от Ильи) | `npx vercel env rm PAUSED production -y` → деплой |
| Логи и ошибки | `npx vercel logs <deployment-url>` или Vercel → Logs; отчёты в Telegram |
| Поменять факты, тон, рубрики | правка `lib/projects.ts` → `npx tsc --noEmit` → превью по обоим проектам → деплой |
| Посев трейлера «Олоида» | Рубрика `trailer` с видео идёт через пост (`alternateRubric` в `lib/projects.ts`), с 2026-10-04 бессрочно. При 3 постах в день это примерно 1–2 трейлера в сутки — так и задумано, пока Илья не скажет иначе. Остановить: убрать `alternateRubric: "trailer"` → `npx tsc --noEmit` → деплой. Видео: `public/media/oloid-teaser-v3-9x16.mp4` (тизер v3, 9:16) |
| Темы рубрик | У рубрик «Олоида» `atmosphere`, `threads`, `about` есть списки `topics`: бот берёт тему, которой не было в недавних постах этой рубрики (`pickTopic` в `lib/run.ts`), тема пишется в историю и в отчёт Telegram. Новые темы — дописать в `topics`; темы, требующие новых фактов, — только вместе с фактами от Ильи |
| Аккаунты Threads | `lib/channels.ts`. Сейчас: `pomazkof` (только Бюро, 11:00, 16:00 и 21:00 МСК, токен `THREADS_ACCESS_TOKEN`) и `oloid` — бренд-аккаунт игры @oloid.vn (только Олоид, голос «мы», 10:00, 15:00 и 20:00 МСК, токен `THREADS_ACCESS_TOKEN_OLOID`). Без токена канал молча пропускается. Новый аккаунт: тестировщик в приложении Meta → токен из генератора → `npx vercel env add THREADS_ACCESS_TOKEN_<ID> production` → запись в `CHANNELS` и кроны `/api/cron?channel=<id>` в `vercel.json` → деплой. Превью и whoami: `&channel=<id>`. Токены и «последний проект» хранятся в Redis по аккаунтам; новый токен из Vercel бот подхватывает сам (сравнивает отпечаток) |
| Статистика | `/api/stats?key=<PREVIEW_KEY>[&days=7][&notify=1]` — метрики всех постов бота (просмотры, лайки, ответы, репосты, цитаты, пересылки) по рубрикам, темам и видео, подписчики аккаунтов. Нужно право `threads_manage_insights` у токена. Каждый понедельник в 10:00 МСК сводка сама уходит в Telegram. Выводы — только по тренду за 2–3 недели; веса рубрик меняет Илья, не бот |
| Ссылки и темы Threads | В ссылках `utm_content=<аккаунт>-<рубрика>` (например, `oloid-atmosphere`): в аналитике сайта и в кликах Threads видно, какие рубрики приводят людей. Темы Threads (`topicTags` у проекта) сменяются — берётся та, что дольше всех не использовалась; у рубрики может быть своя (`topicTag`: dev → «Геймдев», maker → «Нейросети») |
| Картинки к постам «Олоида» | Пул `pictures` в `lib/projects.ts` (11 кадров, одобрены Ильёй 2026-10-05; файлы `public/media/oloid/`, JPEG ≤1440 px). Рубрики с `withPicture` получают кадр по совпадению тегов с темой, без повтора за последние 20 постов; модель и фактчек получают описание кадра. Если Threads не принял картинку — пост уходит без неё (⚠️ в Telegram). Новые кадры — только после проверки на спойлеры и «да» Ильи |
| Цена «Бюро» | 300 ₽ за дело (с 2026-10-09, Илья). Промокодов нет: у buro нет поля `promo`. В `forbidden` — «Промокоды и скидки не упоминать». Общая механика `promo` в типах и `ruleCheck` остаётся для других проектов |
| Поменять время или частоту | `crons` в `vercel.json`. Время в UTC (МСК = UTC+3). На Hobby каждый крон запускается не чаще раза в сутки — слот это отдельная запись `0 <час> * * *`, а не несколько часов в одной. Сверь с текущей документацией Vercel |
| Посмотреть историю постов | Vercel → Storage → база threads-autopost → открыть в консоли Redis, ключ `threads:history` (список JSON-строк) |

Защищённый `/api/cron` вручную вызывай только с `dry=1`:
`curl -H "Authorization: Bearer $CRON_SECRET" "https://<домен>/api/cron?dry=1&project=buro"`

## Перед первым включением

1. Сделай по 5 превью для `buro` и `oloid` и покажи тексты Илье целиком, вместе с причинами отклонений из `rejected`.
2. Сверь факты в `lib/projects.ts` с Ильёй. Особенно важны цена 300 ₽, стол 4–8 гостей, ~90 минут, наличие бесплатного демо. Ссылка «Олоида» — лендинг oloid-game.ru, пока страница Steam не публичная.
3. Уточни у Ильи юридический момент. В РФ запрещено размещать рекламу на ресурсах Meta, а посты о своих платных сервисах могут быть квалифицированы как реклама. Решение за ним, но вопрос стоит задать до запуска.
4. Только после явного «да» сними `PAUSED` и задеплой. На следующий день после первого крона проверь логи и сам пост в Threads.

## Ограничения Threads API (по документации Meta на окт. 2026)
- Текстовый пост — до 500 символов, эмодзи считаются по байтам. Бот держит лимит 450.
- До 250 публикаций через API за скользящие 24 часа.
- Публикация в два шага: `POST /{user-id}/threads` (контейнер), затем `POST /{user-id}/threads_publish`.
- Долгоживущий токен живёт ~60 дней. Бот продлевает его раз в неделю (`th_refresh_token`) и хранит в Redis.
  Если продление сломалось, Илье нужно выпустить новый токен и заменить переменную токена этого аккаунта в Vercel — бот подхватит его сам (чистить Redis не нужно).
