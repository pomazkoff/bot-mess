# Threads-автопостер: «Олоид» + «Бюро Этожеты!»

Дважды в сутки (11:00 и 18:00 МСК) Vercel Cron вызывает `/api/cron`. Бот:
1. Выбирает проект по очереди: Бюро → Олоид → Бюро…
2. Выбирает рубрику по весам и не повторяет прошлую рубрику этого проекта.
3. Генерирует пост через Claude API строго по фактам из `lib/projects.ts`.
4. Прогоняет пост через три фильтра:
   - правила: длина, эмодзи, капс, хештеги, только «своя» ссылка с UTM, ссылка на сайт обязательна в каждом посте;
   - антиповтор: сравнение с последними 40 постами;
   - фактчек: отдельный проход модели, который режет выдуманные цифры, отзывы и спойлеры.
5. Если вариант не прошёл, переписывает его с учётом причины (до 3 попыток). Если не прошли все три, **пропускает день** и шлёт уведомление в Telegram.
6. Публикует пост через официальный Threads API и пишет отчёт в Telegram.

## Что нужно

| Что | Где взять |
|---|---|
| `ANTHROPIC_API_KEY` | console.anthropic.com |
| `THREADS_ACCESS_TOKEN` | долгоживущий токен Threads (см. ниже) |
| `THREADS_USER_ID` | id профиля Threads (можно не задавать, по умолчанию `me`) |
| `CRON_SECRET` | любая длинная случайная строка |
| `REDIS_URL` | Vercel → Storage → Marketplace → Redis (подключён Redis от Redis Inc.; Upstash тоже подойдёт). Бесплатного тарифа хватит |
| `TG_BOT_TOKEN`, `TG_CHAT_ID` | опционально, для отчётов: @BotFather + твой chat id |
| `PREVIEW_KEY` | секрет для холостых прогонов `/api/preview` (публиковать им нельзя) |
| `ANTHROPIC_MODEL` | опционально, по умолчанию `claude-sonnet-5-5` |

### Токен Threads
1. developers.facebook.com → Create App → сценарий **Access the Threads API**.
2. Добавь разрешения `threads_basic` и `threads_content_publish`.
3. Добавь свой аккаунт Threads тестировщиком приложения и прими приглашение в настройках Threads.
   Для постинга в собственный аккаунт App Review обычно не нужен. Проверь это по текущей документации Meta.
4. Получи токен пользователя: генератором в панели приложения или через OAuth.
5. Обменяй его на долгоживущий (~60 дней):
   ```
   GET https://graph.threads.net/access_token?grant_type=th_exchange_token&client_secret=APP_SECRET&access_token=SHORT_TOKEN
   ```
6. Положи результат в `THREADS_ACCESS_TOKEN`. Дальше бот сам продлевает токен раз в неделю и хранит его в Redis.

## Холостой прогон без публикации
```
https://<проект>.vercel.app/api/preview?key=$PREVIEW_KEY&project=buro   # можно добавить &rubric=<id> и &notify=1 (превью в Telegram); поле redis покажет, видна ли база
```
Эндпоинт вообще не подключает модуль публикации, поэтому запостить через него ничего нельзя.

## Первый запуск — сначала вхолостую
```bash
curl -H "Authorization: Bearer $CRON_SECRET" "https://<проект>.vercel.app/api/cron?dry=1&project=buro"
curl -H "Authorization: Bearer $CRON_SECRET" "https://<проект>.vercel.app/api/cron?dry=1&project=oloid"
```
Посмотри 5–10 сгенерированных текстов. Если тон не тот, правь `voice`, `facts` и `rubrics` в `lib/projects.ts`.
Потом запусти без `dry=1`.

## Управление
- `PAUSED=1` — стоп-кран: бот ничего не публикует.
- `DRY_RUN=1` — бот генерирует посты, но не публикует их.
- Расписание задаётся в `vercel.json` (`0 8 * * *` и `0 15 * * *` = 11:00 и 18:00 МСК; на Hobby запуск в пределах часа).
  На тарифе Hobby крон запускается не чаще раза в сутки. Для 2+ постов в день нужен Pro.
- Новые факты (дата релиза, цена Олоида, акции Бюро) добавляй в `facts`. Без этого бот о них не напишет: так задумано.

## Ограничения Threads API
- Текстовый пост — до 500 символов. Бот держит 450, потому что эмодзи считаются по байтам.
- До 250 постов через API за скользящие 24 часа.
- Если тема (`topicTag`) не проходит валидацию, бот повторяет публикацию без неё.
