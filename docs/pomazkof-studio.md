# Личный блог @pomazkof

Аккаунт Ильи в Threads больше не ведёт отдельную ленту «Бюро Этожеты!». Это блог студии Mazkof Games: «Олоид», «Тишина. Последний почтальон», «Твояк», «Этожеты», «Коммуналка», ранний Sic Mundus и страница студии. @oloid.vn не меняется: свой токен `THREADS_ACCESS_TOKEN_OLOID`, свои кроны, свои рубрики.

Код: `lib/studio.ts`, канал в `lib/channels.ts`, крон `api/cron.ts`.

## Черновики

У канала `draftOnly: true`. Крон собирает пост так же, как для публикации (рубрика, проект, факт, картинка, ссылка, три фильтра), но `publishPost` не вызывает. В Telegram уходит сообщение, которое начинается с `черновик @pomazkof`, затем текст, строка `картинка:` и строка `ссылка:`. Под текстом кнопки «Опубликовать» и «Пропустить». Токен канала — прежний `THREADS_ACCESS_TOKEN` и ключ Redis `threads:token` без суффикса. Токен «Олоида» этот слот не читает.

Кнопки есть только у черновиков `draftOnly`. @oloid.vn их не получает и публикуется как раньше.

Перед сообщением пост целиком пишется в Redis, ключ `threads:draft:<id>`, TTL 7 суток: текст, медиа, ссылка, проект, рубрика и остальные поля для `publishPost` и истории. В кнопках `callback_data` — `pub:<id>` и `skip:<id>`.

Прошедший проверки черновик сразу пишется в общую историю без `postId`. Так следующий слот берёт другую рубрику, другой проект и другой факт, даже если кнопку ещё не нажали. В статистику Threads такая запись не попадает.

«Опубликовать» берёт черновик из Redis и вызывает тот же `publishPost`, что обычный слот, с токеном канала (`THREADS_ACCESS_TOKEN`). На время публикации ставится замок `SET NX` (`threads:draft:<id>:lock`). Повторное нажатие пост не создаёт. После успеха статус черновика — `published`, в историю дописывается `postId` (если записи не было, кладётся полная, как при обычной публикации). Кнопки снимаются, внизу сообщения — «✅ Опубликовано» и ссылка на пост, если Threads её отдал. Если картинку Threads не принял, уходит тот же текст без неё. Если публикация упала, замок снимается, кнопки остаются, в ответ — «Ошибка публикации: …».

«Пропустить» ставит статус `skipped`, снимает кнопки и дописывает «⏭ Пропущено». В Threads ничего не уходит. Запись в истории без `postId` остаётся, следующий слот её учитывает.

Неизвестный или протухший id — ответ «Черновик устарел». На каждый подлинный callback бот вызывает `answerCallbackQuery`.

Вебхук — `POST /api/telegram`. Заголовок `X-Telegram-Bot-Api-Secret-Token` должен совпасть с `TELEGRAM_WEBHOOK_SECRET`. Чужой чат (не `TG_CHAT_ID`) кнопки не обслуживает. Пока секрет не задан, вебхук отвечает 401.

`PAUSED=1` и `DRY_RUN=1` по-прежнему не дают крону собрать новый черновик. Уже присланная кнопка «Опубликовать» постит в Threads по-настоящему: это ручное подтверждение, не слот крона.

Чтобы публиковать слоты сразу, без кнопок, убери `draftOnly` (или поставь `false`) и задеплой.

Старые ролики «Дело №1» в `lib/scheduled.ts` на @pomazkof больше не выходят: канал не ведёт проект `buro`.

## Кнопки: секрет и вебхук

Бот до этого только отправляет сообщения (`sendMessage`) и `getUpdates` не вызывает. Скрипт ниже ставит вебхук на этого бота и заменяет предыдущий, если тем же токеном уже пользовался другой приёмник. `allowed_updates` — только `callback_query`, чтобы апдейты сообщений не копились.

Секрет для Telegram: 1–256 символов, только `A–Z`, `a–z`, `0–9`, `_` и `-`.

```bash
openssl rand -hex 24 | npx vercel env add TELEGRAM_WEBHOOK_SECRET production
npx vercel deploy --prod
```

Тот же секрет и `TG_BOT_TOKEN` нужны в окружении команды. Регистрировать вебхук после деплоя, иначе Telegram стучится в старую версию:

```bash
TELEGRAM_WEBHOOK_URL=https://threads-autopost-six.vercel.app/api/telegram \
  node scripts/set-telegram-webhook.mjs
```

Скрипт вызывает `setWebhook` с `secret_token` и `allowed_updates: ["callback_query"]`, затем печатает `getWebhookInfo` без секрета и без токена. Пока вебхук не зарегистрирован, кнопки в Telegram видны, но нажатие боту не приходит.

## Расписание

Три поста в сутки, вечерний слот на месте. Времена те же, что были у «Бюро», чтобы не сдвигать кроны «Олоида»:

| МСК | UTC в `vercel.json` |
|---|---|
| 11:00 | `0 8 * * *` |
| 16:00 | `0 13 * * *` |
| 21:00 | `0 18 * * *` |

## Как выбирается пост

Рубрики по очереди, кто дольше не выходил: «как делаются игры», дневник, релизы и новости, вопрос, мысль продакта. Ничья — этот порядок.

Проект не повторяет предыдущий пост. Sic Mundus берётся только в дневник: без ссылки, без скриншота, без цены и без срока релиза. Один и тот же факт не берётся снова среди последних 10 постов блога.

Ссылка примерно через пост: 1-й, 3-й, 5-й… На вопросе это `https://mazkof.games/` (кнопка «Предложить идею игры»). В остальных рубриках чаще якорь `https://mazkof.games/#oloid` и соседние, а каждый второй пост со ссылкой — магазин, если он у проекта есть. У «Тишины» магазин `https://apps.apple.com/app/id6831583069`, у «Олоида» — `https://apps.apple.com/ru/app/id6817809325`.

Событие «Первые письма» можно называть только до 21.11.2026 13:55 МСК.

Голос: от первого лица, строчные, короткие абзацы через пустую строку, ссылка на своей строке. У «Этожет» остаётся одна мемная отсылка к детективу. Жеглов, Штирлиц и Пуаро нельзя. Цена дела — 100 ₽, временная.

## Что режется

Черновик отклоняется, если в нём вайбкодинг («вайб», «навайбкожено»), «нейросеть пишет код», ИИ-агент, Cursor, Claude, pull request, отдельное «лей», `vercel.app`, промокоды OMSK / GUEST / PLAYTEST, ShopID, ИНН, спойлеры из паспорта и числа не из факта этого поста. Фраза «тексты пишет нейросеть под компанию» для «Этожет» и «ИИ использовался как инструмент» для «Олоида» остаются допустимыми.

## Картинки

`public/media/tishina/` — восемь скринов App Store, без перекраски. `public/media/kommunalka/` — план, портреты, кухня и `stats.jpg`. Пост со статистикой «Коммуналки» берёт `stats.jpg`. На самой инфографике больше цифр и строка про дверь: в текст поста это не переписывается, в Threads картинка уйдёт только после того, как Илья увидит черновик. У «Олоида» в блоге — уже лежащие в репозитории кадры без тайной комнаты. «Твояк», «Этожеты» и Sic Mundus пока без картинки.
